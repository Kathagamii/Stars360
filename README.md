# Stars360

Интерактивный веб-планетарий: выберите любую точку на Земле и увидьте
звёздное небо над ней **прямо сейчас** — с реальными положениями звёзд,
Солнца, Луны и планет, рассчитанными астрономически для выбранных
координат и времени.

## Стек

- **React 19 + TypeScript + Vite** — приложение и сборка.
- **Three.js + @react-three/fiber** — рендер небесной сферы (WebGL, точки
  вместо DOM-элементов — тысячи звёзд без просадки FPS).
- **[astronomy-engine](https://github.com/cosinekitty/astronomy)** —
  астрономические расчёты (эфемериды Солнца/Луны/планет, звёздное время,
  прецессия/нутация, преобразование координат).
- **[satellite.js](https://github.com/shashwatak/satellite.js)** — SGP4/SDP4:
  расчёт положения искусственных спутников по реальным орбитальным элементам
  (TLE) для текущего времени и наблюдателя.
- **Leaflet + react-leaflet** — интерактивная карта Земли.
- **Zustand** — состояние приложения.
- **Tailwind CSS v4** — стили.
- **tz-lookup** — определение часового пояса по координатам (офлайн, без API).

## Установка и запуск

```bash
npm install
npm run dev       # http://localhost:5173
```

Продакшн-сборка:

```bash
npm run build      # tsc -b && vite build → dist/
npm run preview    # локальный просмотр production-сборки
```

## Откуда берутся астрономические данные

**Каталог звёзд не выдуман — он взят из реальных астрономических
источников** и один раз конвертирован в компактный JSON во время сборки
данных (не во время выполнения приложения):

| Источник | Что даёт |
|---|---|
| [d3-celestial](https://github.com/ofrohn/d3-celestial) (Olaf Frohn, BSD) | Положения и блеск ~5000 звёзд до 6ᵐ (на основе каталога Hipparcos), линии и названия 88 созвездий, объекты Мессье и яркие объекты глубокого космоса |
| [HYG Database](https://github.com/astronexus/HYG-Database) (astronexus) | Реальное расстояние (по параллаксу) и спектральный класс для каждой звезды по номеру Hipparcos |
| [CelesTrak](https://celestrak.org) (публичные GP/TLE-элементы) | Актуальные орбитальные элементы для 9 отобранных спутников (МКС, Тяньгун, «Хаббл», GPS, GOES-16, NOAA-20, Landsat 8, Sentinel-2A, OneWeb) |

Готовые данные лежат в `src/data/*.json` (собираются один раз, в
рантайме уже не запрашиваются). Чтобы обновить или заменить источник:

```bash
npm run data:fetch   # скачивает сырые каталоги в dataprep/
npm run data:build   # пересобирает src/data/{stars,constellations,deepsky,satellites}.json
```

Чтобы **заменить источник данных** на другой (например, полный каталог
Hipparcos или Gaia), достаточно переписать `scripts/build-data.mjs` так,
чтобы он выдавал JSON с той же формой (см. `src/types/index.ts`:
`StarRecord`, `ConstellationRecord`, `DeepSkyRecord`, `SatelliteRecord`) —
остальной код астрономии и рендеринга не привязан к конкретному источнику.
Чтобы добавить/заменить спутник в подборке, поменяйте `CURATED_SATELLITES`
в `scripts/build-data.mjs` (сопоставление ключа с именем объекта в
скачанном TLE-файле) и добавьте описание в `src/data/satelliteFacts.ts`.

Положения **Солнца, Луны и планет** не кэшируются — они каждый раз
считаются на лету через `astronomy-engine` (реальные эфемериды, не
таблицы). Положения **спутников** тоже не кэшируются — они каждый кадр
пересчитываются по модели SGP4 (`satellite.js`) из реальных орбитальных
элементов, зафиксированных на момент `data:fetch`.

⚠️ Орбитальные элементы (TLE) спутников устаревают за 1-2 недели
(атмосферное торможение, манёвры коррекции орбиты) — в отличие от звёзд,
это не «вечные» данные. Чтобы позиции спутников остались точными,
периодически повторяйте `npm run data:fetch && npm run data:build`.

## Где находится астрономическая логика

Вся астрономия отделена от UI и лежит в `src/astronomy/`:

- **`engine.ts`** — обёртка над `astronomy-engine`: наблюдатель
  (`Observer`), положение тел (Солнце/Луна/планеты) в горизонтальных
  координатах, фаза Луны.
- **`coords.ts`** — преобразование координат:
  - каталожные RA/Dec (J2000) → единичный вектор в системе EQJ;
  - матрица поворота EQJ → HOR (горизонтальная система) для текущих
    времени и наблюдателя (`Astronomy.Rotation_EQJ_HOR`);
  - пакетное применение этой матрицы сразу ко всем звёздам одним проходом
    (без пересчёта тригонометрии на звезду каждый кадр) — см. ниже.
- **`selection.ts`** — превращает выбранный объект в готовые для показа
  данные (высота/азимут, расстояние, спектральный класс и т.д.), используя
  тот же пайплайн EQJ→HOR, что и рендер, — числа в панели **точно
  совпадают** с тем, что нарисовано на экране.
- **`constellationInfo.ts`** — яркие звёзды и объекты созвездия (по
  реальным данным), плюс оценка «в каком месяце лучше видно», вычисляемая
  из эклиптической долготы Солнца (не выдумана, а посчитана).
- **`satellites.ts`** — обёртка над `satellite.js`: SGP4-пропагация TLE в
  альт/азимут/дальность для наблюдателя, орбитальный период и наклонение
  из mean-элементов, приближённая (цилиндрическая, без полутени) проверка
  «освещён ли спутник Солнцем сейчас» для честного статуса видимости
  невооружённым глазом.
- **`search.ts`** — индекс поиска по звёздам/созвездиям/планетам/спутникам.

### Как именно считаются альт/азимут

1. У каждой звезды в каталоге есть RA/Dec на эпоху J2000.
2. Прямо перед рендером один раз за кадр строится матрица поворота
   `Astronomy.Rotation_EQJ_HOR(date, observer)` — она учитывает широту,
   долготу, высоту наблюдателя, местное звёздное время, прецессию и
   нутацию.
3. Эта матрица применяется сразу ко всем ~5000 звёздам (и точкам линий
   созвездий, и объектам глубокого космоса) в одном плотном цикле — это
   дёшево (тысячи умножений 3×3 матрицы на вектор), поэтому небо плавно
   двигается на 60 FPS даже при ускоренной перемотке времени ×1000.
4. Для панели объекта то же самое считается точнее — с учётом рефракции
   (`Astronomy.HorizonFromVector(vec, "normal")`).

Солнце/Луна/планеты используются напрямую через
`Astronomy.Equator()` + `Astronomy.Horizon()` — их мало (9 тел), поэтому
для них не нужна пакетная оптимизация.

## Структура компонентов

```
src/
  astronomy/     — вся астрономия (без UI)
  data/          — собранные каталоги (stars/constellations/deepsky/
                   satellites.json) + небольшие кураторские данные (факты
                   о созвездиях и спутниках, русские названия ярких звёзд,
                   данные о планетах)
  store/         — Zustand-стор + отдельные "часы" симуляции (simClock),
                   которые не дёргают React 60 раз в секунду
  hooks/         — useSimTime (троттлинг часов для UI-текста)
  utils/         — форматирование, геокодирование, часовые пояса, цвет звёзд
  components/
    Map/         — WorldMap, выбор точки, карточка выбора
    Sky/         — SkyScreen (экран целиком) →
                     SkyCanvas (сцена Three.js) →
                       StarField, ConstellationLines, DeepSkyObjects,
                       CelestialBodies (Солнце/Луна/планеты), Satellites
                       (искусственные спутники, режим «Спутники»), SkyDome
                       (градиент неба), HorizonGround + Terrain (линия
                       горизонта, стороны света, силуэт рельефа),
                       LookControls (вращение обзора),
                       Ticker (симуляционные часы внутри Canvas)
                   TopBar, BottomNav, ObjectInfoPanel,
                   ConstellationInfoPanel, TimeController, Search,
                   SatelliteBearings (подсказки-стрелки к спутникам,
                   находящимся вне текущего поля зрения)
```

## Производительность

- Звёзды/объекты глубокого космоса — не DOM, а `THREE.Points` с
  собственным шейдером (размер и цвет — атрибуты вершин), обновление
  позиций — прямая запись во `Float32Array` без аллокаций на кадр.
- «Симуляционные часы» (`store/simClock.ts`) отделены от Zustand: сцена
  читает их каждый кадр напрямую, а UI-текст (часы, дата) подписан на
  них через `useSyncExternalStore` с троттлингом — дата в шапке не
  дёргает рендер всего дерева 60 раз в секунду.
- Экран карты и экран неба грузятся отдельными чанками
  (`React.lazy` в `App.tsx`) — Three.js/astronomy-engine/каталог звёзд не
  загружаются, пока пользователь не откроет небо.

## Известные упрощения

- Часовой пояс места наблюдения определяется офлайн по координатам
  (`tz-lookup`), без сетевого запроса.
- Название ближайшего города для выбранной точки на карте определяется
  через бесплатный Nominatim (OpenStreetMap); если сервис недоступен —
  показываются координаты.
- «Лучшие месяцы для наблюдения» созвездия — приближённая оценка на
  основе положения Солнца по эклиптике (без учёта уравнения времени),
  для ориентира, а не для точных расчётов видимости.
- Показаны 7 больших планет, Солнце, Луна, ~5000 звёзд до 6ᵐ и ~140
  объектов Мессье/ярких объектов глубокого космоса — этого достаточно
  для убедительного неба невооружённым глазом; при желании каталог можно
  расширить (см. «Откуда берутся данные» выше).
- Спутники — курируемый список из 9 хорошо известных объектов (не весь
  каталог из десятков тысяч отслеживаемых аппаратов), с реальными
  орбитальными элементами (TLE), но стареющими за 1-2 недели без
  повторного `data:fetch`. «Освещён ли Солнцем сейчас» считается по
  упрощённой цилиндрической модели тени Земли (без полутени) — для
  статуса видимости невооружённым глазом этого достаточно, но это не
  точная модель затмений.
